# 01 需求与成功标准

## 用户、目标与输入

员工提出制度或产品问题，希望得到能核对原文的可靠答复。输入是 `question` 和可选 `history`（按顺序的 `user`/`assistant` 消息）。资料为带 `document_id`、`version_date`、标题、主题和原文片段的合成 FAQ/制度。

## 范围与输出

工具为 `search_documents`（检索文档元数据）和 `read_snippet`（读取原文）。Agent 输出 `task_status`、`answer`、`citations`（文档 ID、版本日期、片段 ID、原文、哈希）、`evidence_gaps`、冲突标志、待澄清问题，以及每步动作、参数、工具结果和下一动作。可用 CLI 离线或接入 DeepSeek；不连接企业内部资料。

## 成功标准

1. 明确答案：仅在检索并读取支持问题的原文后回答，引用与原文一致。
2. 文档冲突：D01 规定 30 天、D02 规定 15 天且无范围或优先级时，列出双方引用，标记需澄清，不能擅选较新的 D02。
3. 资料外问题：无来源时说明资料缺口，引用为空。
4. 改写后的相似问题：同义说法仍能命中相关制度，并按同样的冲突规则处理。
5. 上下文追问：当前问题含省略表达时利用对话历史检索，并引用相应 FAQ。
6. 工具失败：错误步骤标为失败，模型观察后可选择重读、补检索或停止；不得引用读取失败的片段。
7. 证据变化：替换制度原文后，引用与答案随之改变；消除冲突后不再输出冲突。
8. 上限：达到模型步数或业务工具调用上限，明确返回未完成。

Mock 路径用于离线回归；至少两条真实模型 Trace 用于证明工具观察影响下一步动作。不得把预设 Mock 决策当作真实模型 ReAct 证据。
